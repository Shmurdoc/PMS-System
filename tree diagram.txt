 SECTION 3 - REQUEST FLOW:  POST /api/v1/rooms
================================================================================

  1. RoomsController.Create receives the command DTO from the request body.
  2. Controller calls _mediator.Send(command).
  3. MediatR resolves CreateRoomHandler from DI (scoped to this request).
  4. Handler takes IApplicationDbContext + IMapper via constructor injection.
  5. Handler queries Rooms / Properties, mutates tracked entities, then calls
     SaveChangesAsync() ONCE  ->  one transaction  (no repository layer,
     no IUnitOfWork - the scoped DbContext IS the unit of work).
  6. Handler returns Result<RoomDto>.SuccessResult(dto)  or  a failure.
  7. Controller maps Result -> 201 / 200 / 400 / 404.
  8. ApiResponseMiddleware wraps the JSON body in the ApiResponse envelope
     (success, error, timestamp, requestId) before it leaves the process.

  Read side (CQRS queries DO exist): e.g. GetRoomQuery / GetRoomHandler in
  Aquri.Application\Rooms\Queries.cs  (IRequest<RoomDto?> on IApplicationDbContext).


  AUTH FLOW:  POST /api/v1/auth/login
  ------------------------------------------------------------------------
   LoginCommand -> LoginHandler
      1. look up user by email (AquriDbContext)
      2. verify PBKDF2 hash  -> IPasswordHasher (Pbkdf2PasswordHasher)
      3. issue JWT          -> ITokenService   (JwtTokenService)
         claims: NameIdentifier, Email, Name, Role
      4. controllers guard with [Authorize(Roles="admin,manager")]
         role constants live in Domain (AppRoles)
   GET /api/v1/auth/me  reads the NameIdentifier claim back -> profile.
   DbSeeder runs at startup (idempotent: skips if Users.AnyAsync()),
   wrapped in try/catch so the API boots even when Postgres is down.

 SECTION 6 - NOTES & OBSERVATIONS
================================================================================
 1. CQRS STATUS: mostly CQRS. Commands and Queries both flow through MediatR
    (Rooms has Commands.cs + Handlers.cs + Queries.cs). Write side returns
    Result<T>; read side returns DTO? directly. Some older controllers call
    _mediator.Send(command).Result - blocking async (deadlock risk).

 2. UNIT OF WORK: no repository pattern, no IUnitOfWork. The scoped
    AquriDbContext is the unit of work; one SaveChangesAsync per request.

 3. DEAD PACKAGE REFERENCES: Infrastructure's csproj pulls StackExchange.Redis,
    Minio, Hangfire, QuestPDF, Ardalis.Specification - none are used anywhere
    in the code (grep = 0 hits). Runtime data store is PostgreSQL only.

 4. DOCKER MISMATCH: docker-compose only defines db + api. nginx.conf (TLS
    reverse proxy) and certs/ (empty) are never started by compose. The
    second Dockerfile (Aquri.API/Dockerfile) is not referenced by compose
    either. Port 8080 is consistent between root Dockerfile and nginx.conf.

 5. SECURITY NOTE (resolved): docker-compose no longer carries credentials —
    POSTGRES_PASSWORD and JWT_KEY come from .env (gitignored; .env.example
    ships placeholders and compose refuses to boot without them). appsettings.json
    ships empty and Program.cs fails fast on a missing value; no fallback
    secrets remain.

 6. EMPTY / LOOSE ITEMS: Aquri.Domain/Common/ is empty (architecture.md mentions
    IRepository.cs/IUnitOfWork.cs but they do not exist); Infrastructure/ at
    repo root is not in Aquri.sln; NuGet.Config.bak is a disabled NuGet config.

 7. TRANSITION: codebase is mid-migration from flat Application folders to
    vertical slices (see docs/conventions.md and docs/roadmap.md).
